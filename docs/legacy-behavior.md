# 旧系统行为审计

审计来源：`home/src/page/Questions`、`Letter`、`ClearCache`、`store/questions.ts`、`server/qa.ts`、`types/qa.ts` 和相关工具。

## 已确认行为

- 缺少 `type` 时为填空题；旧 MultipleChoice 实际是单选 key，不是多选集合。
- 答案先精确比较，再执行 NFKC + 去 Unicode 空白/标点 + 小写比较。
- 只有选择题答错会累计惩罚；默认惩罚是 3 分钟、第二次永久锁定；配置耗尽后持续使用最后一项。
- 题目 `updated` 参与缓存 key，因此后台更新题目会自然形成新进度记录。
- 多题按 `qas` 顺序筛选；缺失 step 被跳过；全部缺失进入迷失状态。
- 多题恢复时进入第一道未完成题，全部完成时停在最后一题。
- `autoNext` 等待依赖媒体：无媒体约 1.5 秒，图片/文本约 5 秒，视频等待播放结束。
- 通知每 5 秒轮询，页面不可见时暂停；一次只弹出一个未见消息。
- Letter 缓存优先、网络更新，缓存 key 为 `letter_records_cache`。

## 遗留耦合与待决策

- 旧单题走 Store，旧多题协调多个 compact `QuestPage`；新项目不兼容该组件结构。
- `debug=1` 可绕过时间窗口。上线前需决定删除、仅开发环境允许或增加鉴权。
- 内容标记包括 `[[高亮]]`、`((文字||url))`、`{{图片}}`、`<<视频||封面>>`；必须用安全 AST 渲染，不能注入 HTML。
- 埋点已改为类型化运营事件：保留原始回答、标准答案、题面、进度和媒体/线索定位信息，以支持人工判断与远程提示；失败不阻塞业务，且仅 `/questions/` 正式构建可启用。
- 最终关、自动媒体、多题完成特效要用显式事件编排取代散落定时器。
