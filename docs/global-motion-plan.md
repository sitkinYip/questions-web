# 全局动画增强与双端适配执行方案

状态：已完成共享动画底座与全局弹层迁移，已加入信纸收起、Tabs 内容进入和开发验收场。具体实现边界见 `docs/ui-system.md` 的“全局动画生命周期”章节；以下保留执行前审计与验收标准。

## 目标

延续星图、金色光效和现有浅色主题，提高交互的重量感、方向感与完整性。每个动画组件同时定义进入、退出、中断、恢复和 reduced-motion 行为。PC 与移动端按实际布局匹配运动方向；关闭动作清晰、及时，不让内容突然消失，也不靠延长等待制造质感。

## 工程结构

### 1. 统一运动语义

建立小型 motion 契约，沿用 React、Radix 与原生 CSS，第一阶段不新增动画库。

- placement：center / left / right / bottom，决定位置、transform-origin、进入与退出方向。
- preset：dialog / sheet / popover / toast / panel / ceremony，描述交互用途。
- phase：entering / open / exiting / closed；调度另记录 suspended，不能用 closed 表示临时被媒体覆盖。
- tokens：按用途定义 enter、exit、press、stagger、ease-enter、ease-exit；不在 feature 中再散落 220/340/760ms。
- 响应式 placement 由共享布局能力解析一次，CSS 消费结果。保留现有 1100px 桌面能力边界；对奖品当前 760px 底部切换规则明确决策后统一，不能让 JS、样式和动画各用不同断点。建议奖品在非桌面布局使用 bottom，PC 使用 right。
- 触控能力决定 hover 与手势可用性，宽度决定布局；不按设备 UA 推断。

建议文件职责：

| 位置                                | 职责                                                           |
| ----------------------------------- | -------------------------------------------------------------- |
| `shared/motion/`                    | phase/preset 类型、非 Radix 场景的 presence 生命周期和中断规则 |
| `components/ui/Dialog.tsx`          | 统一呈现、关闭完成、焦点与可访问性；不管理业务数据             |
| `components/ui/Sheet.tsx`           | 响应式 placement 与抽屉外壳，移除业务 CSS 对位置的反向覆盖     |
| `components/ui/OverlayProvider.tsx` | 请求、退出、覆盖与恢复的调度规则                               |
| `styles/foundation/tokens.css`      | 跨组件运动时长、缓动和幅度 token                               |
| `styles/components/`                | preset 与 data-state/placement 的样式绑定                      |
| `styles/effects/*keyframes.css`     | 唯一 keyframes 定义位置                                        |
| feature                             | 业务状态及允许保留的展示快照；特有星图、信纸和演出内容         |

新增样式模块同步更新 index.css 与架构检查清单，不绕过现有所有权、体积与主题约束。

### 2. 关闭生命周期先于视觉增强

1. 用户关闭后立即停止播放、阻止重复提交或重复确认；业务取消不等待动画。
2. 保留可安全展示的内容快照，组件进入 exiting；快照不得用于授权或再次提交。
3. 面板和遮罩执行退场；退场期间底层页面不能被误点。
4. 确认退场完成后卸载、释放滚动锁和调度占用，再恢复焦点。
5. 优先让 Radix 原生 presence 驱动 CSS animation 的卸载，先保证调用方不提前移除整个组件。
6. 自定义菜单/页面才使用共享 presence；过滤子元素冒泡的结束事件，处理 animationcancel、reduced-motion、无动画和组件销毁；统一提供有界兜底，禁止每个业务复制 setTimeout。
7. 关闭中再次打开可取消退出；旧回调不能卸载新打开的实例。路由离开、退出账号、权限变化直接清理敏感内容，不为动画保留旧数据。
8. 媒体覆盖详情属于 suspended：保留详情滚动位置与焦点锚点，不重复播放完整开场。紧急确认按优先级抢占，普通弹层等退场结束再交接。

### 3. 运动层与视觉层分离

- 外层控制整体位移、缩放和透明度；内层拥有文字错峰、边缘高光、星纹与粒子。
- 同一 DOM 的 transform 不同时交给入场、拖动、缩放和 hover。
- 出场开始时停止持续轨道及新粒子，光晕先收束，主体沿来源方向离开；不再单纯瞬间降到 opacity=0。
- 所有关闭入口复用同一个动作：关闭按钮、Esc、遮罩、完成操作、手势与程序关闭。

## 双端运动规范（初始调校范围）

| 场景                   | PC                                     | 手机 / 触控                                  | 退场规则                                  |
| ---------------------- | -------------------------------------- | -------------------------------------------- | ----------------------------------------- |
| 奖品详情               | 右侧滑入，300–380ms，轻微缓停          | 底部上升，320–400ms，轻微回弹                | PC 向右、手机向下，220–280ms，无退场回弹  |
| 导航抽屉               | 按真实侧边进入                         | 仍为侧边布局的导航继续水平运动               | 原路返回，不把全部手机抽屉强制改成 bottom |
| 居中弹窗               | 轻缩放与 8–16px 上移，240–320ms        | 保持居中者同样轻缩放；全屏/底部者按实际布局  | 缩回并轻移，180–240ms，遮罩不提前消失     |
| 头像 / 主题 / 行菜单   | 从触发器锚点展开，160–220ms            | 触控点击反馈；如布局不同则采用对应 preset    | 收回锚点，140–200ms                       |
| 图片 / 视频剧场        | 外壳轻缩放，内容有独立进入层           | 不占用双指和拖动的 transform                 | 关闭即停播放，外壳退场；返回原详情位置    |
| Tabs / 页面内容        | 活动指示与内容淡入、小位移，160–240ms  | 横向 Tabs 跟随切换方向；大列表不整体大幅横飞 | 保持固定导航和滚动范围；最新操作优先      |
| 升级 / 完成 / 信件演出 | 容器及时进入，内部演出可有更强节奏     | 降低粒子与大面积模糊，保留核心仪式           | 清晰收束；不为装饰延迟业务结果或返回      |
| 按钮 / 卡片 / Toast    | hover 聚光、按压回弹、原有 Toast swipe | 按压反馈，无粘滞 hover                       | 手势释放、取消、禁用状态均有定义          |

时长以浏览器实测调校，不用同一个长动画覆盖全站。装饰可继续演出，但主要操作不等待文字错峰或光效完成。

## 全局覆盖与执行顺序

### 第一批：底座与代表场景

- 建立使用清单：每个入口记录 PC/手机位置、open/close 路径、是否提前卸载、所有者、测例。
- 完成 Sheet / AppDialog 的 placement、enter/exit 与 Overlay 交接契约。
- 先迁移奖品详情、媒体覆盖详情、一个普通通知弹窗，覆盖三种典型生命周期。
- 验证通过后才推广，不先全局替换 animation 属性。

### 第二批：所有弹层和菜单

- 移动头像导航、PC 头像菜单、ThemeMenu、MailboxRow 菜单。
- 线索、组合线索、通知正文与通知列表、媒体查看器。
- 等级提升、完成反馈、版本档案、缓存确认、头像裁剪。
- 同步巡查 AppDialog/Sheet 所有调用方和直接使用 Radix 的入口，清除条件卸载造成的退场截断。
- Toast 作为已具备退出逻辑的对照回归，不重复改写业务。

### 第三批：全局交互与仪式增强

- 启程 / 收藏 / 来信 / 护照导航、Tabs 切换、列表进入、空态/加载/错误切换。
- 卡片、按钮、表单反馈和媒体切图：统一按压、取消、禁用与 focus 反馈。
- 信纸开合/翻页、祝福与片尾、升级和完成演出：检查方向、快速连续操作、跳过/返回与清理，保持现有叙事节奏。
- 浅色和深色分别调光效，不依赖高饱和或高模糊增加游戏感。

### 第四批：验收与交付

- 提供开发专用动画验收页面：模拟各类内容、长正文、长列表、打开/关闭/重复切换，双端切换；不写入生产业务。
- 增补架构检查：共享组件成对定义 enter/exit；禁止 feature 重写通用外壳 animation；新增硬编码计时须有明确业务理由。
- 交付逐项覆盖矩阵、浏览器录制或关键帧证据、性能观察及测试结果。

## 验收标准

1. 奖品移动端向上打开、向下退出；PC 从右进入、向右退出。布局方向与动画同源。
2. 关闭中间帧存在且运动可见；结束后 DOM、遮罩、焦点陷阱、滚动锁正确释放。
3. 各入口分别验证按钮、Esc、遮罩关闭及程序关闭；不只检查最终元素消失。
4. 快速开关至少五次、退出中重新打开、切断点、打开期间切主题，不闪屏、不丢内容、不留遮罩。
5. 详情 → 媒体 → 返回详情保留滚动位置；播放和焦点只属于当前活动层。
6. PC 1100/1366/1920、移动 320/390/430 以及短屏，检查位移轴、锚点、遮挡、内容布局与滚动。
7. Chromium 与移动 WebKit 使用正常动画验证中间状态；reduced-motion 单独验证，不能全程关闭动画后宣称动画测试通过。
8. reduced-motion 取消长距离位移、回弹和持续粒子，只留短淡入淡出或即时反馈；不得因 animationend 不触发卡住关闭。
9. 键盘焦点返回触发器；触发器已卸载时回到合理的页面锚点；退场阶段不重复响应业务操作。
10. 以 transform/opacity 为主，Chrome Performance 检查主交互阶段的长任务、布局抖动及持续合成开销；低端触控设备减少同时运行的装饰层。
11. 完成格式、样式架构、类型、单元及相关 E2E 检查；对实际视觉做本地 Chrome 复核。

## 风险与边界

主要风险是弹层释放时机、媒体播放、焦点和连续演出顺序，不能只把退场时长加长。优先保住业务状态机和交互响应，再调视觉。保留现有设计语言与工程栈；只有原生方案遇到明确且可复现的能力瓶颈时，再评估新增依赖。
