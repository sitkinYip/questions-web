日期：2026-08-28。**新后端和两端正式站点已替换，旧容器停用；公网验收通过。** 当前部署状态见 [正式部署记录](./production-deployment-20260828.md)。下文保留开发和上线前各阶段记录，不能把早期阻塞作为当前状态。

业务与数据设计见 [backend-rebuild-design.md](./backend-rebuild-design.md)。替换已获授权，执行仍遵循完整备份、独立新库、验收后切入口的顺序；不直接让新二进制打开旧线上库，也不提前清理回退材料。

## 1. 实施顺序与验收门槛

### 阶段 0：线上只读审计与安全准备

确认 PocketBase 版本、实际启动命令、工作目录、数据目录、宿主机挂载、镜像/CPU 架构、代理域名、其他应用共用集合情况。用户可以在浏览器里自行登录，不需要把密码粘贴进聊天。

获取集合结构和权限快照，检查现有 `users` 与媒体存储的用途。创建完整数据备份，在隔离实例验证恢复；外部对象存储和媒体单独登记。已有的 27 道题等内容导出只用于重配，不替代这一备份。

交付：环境清单、只读审计结果、备份与恢复验证记录、确认后的服务端版本、独立测试环境。禁止仅因为 Questions 不要旧数据就删除共享实例的全部集合或数据目录。

### 阶段 1：建立可重复的服务端工程

在 `sitkin-pb-backend-management/backend/` 建立迁移、JS hooks、领域辅助函数、契约、测试和部署说明；只操作本地或隔离实例。

建议结构：

```text
backend/
  pb_hooks/            # 路由、认证、校验和业务命令
  pb_migrations/       # 按版本固定的集合、索引与规则
  contracts/           # API schema、错误码与生成类型
  tests/               # 纯规则测试与真实 PB 集成测试
  fixtures/            # 无私密信息的最小测试数据
  scripts/             # 启停测试实例、导入样例、验证
  deploy/              # 固定版本的部署构建说明
```

不提交 `pb_data`、认证令牌、真实密码、数据库导出或原始私人信件。生产镜像/发布包包含固定 PocketBase 二进制和匹配版本的 hooks/migrations；不使用浮动 latest。

契约以服务端仓库为源，生成两个前端各自可提交的类型，不通过绝对路径跨仓库导入。玩家端保留 Zod 入站校验；契约变更有版本、样本与兼容性测试。

验收：空目录可从迁移启动；重复启动不重复初始化；迁移失败不出现半套结构；实际 PB JS 引擎通过中文/Unicode 判题用例。版本升级与业务重构分开验收，不未经验证覆盖旧二进制。

### 阶段 2：账号与单题场次最小闭环

完成管理员建玩家、首次改密、个人资料、账号禁用、等级定义、题目发布、单题场次发布、下发、入场、判题、经验流水、进度恢复。先做够用的管理与玩家页面，不等待所有高级配置页面完成。

验收：管理员创建两个用户，同场分别下发；用户互相不可见；其中一人完成后只增加自己的经验；换设备恢复；禁用账号后现有令牌也不能继续答题。

### 阶段 3：多题、场次资格与现场运营

完成多题顺序、时间窗、入场等级快照、惩罚、人工通过、解锁、撤回、延时、重新下发和发布版本冻结。补齐场次编辑器、指定用户/所有有效用户选择和实时进度页面；全员下发保存当次接收快照，重复请求不扩大范围，已完成用户默认不再下发。

验收：等级上下界生效；场内升级不中断；重发产生新 ID 并正常再次加经验；旧分配不改变；修改草稿不影响已分配内容；同一题复用两次时进度互不串联。

### 阶段 4：奖品、核销、线索和通知

完成固定触发的发奖规则、用户奖品、管理员核销/撤销核销、专属领取信息、线索解锁、叙事内容授权、通知与跨设备已读。接入现有媒体编辑器，但划分公共装饰资源与私密领取/叙事资源。

验收：一次完成只发一份权益；重发新场次再次获得；两个管理员并发核销只成功一次；用户不能核销；未解锁线索和别人的取件信息在接口、关联展开、文件访问中均不可读。

### 阶段 5：完整前端适配与样例复配

保留原视觉和演出，完成我的场次、个人中心、经验、奖品与历史入口。答题改为服务端请求；取消本地权威进度和包含答案的客户端埋点。退出和账号切换清理业务缓存。

将原始导出的内容经过审查转换为新模型样例，选择至少一组单题、多题、选择题、媒体、组合线索、Letter/Bless 和实物奖励场景。敏感姓名、头像、密码和实际柜码不进入公开测试夹具。

验收：现有视觉、媒体、BGM、主题与完成时序回归；移动端可以完成登录到核销前的全流程；用户确认复配内容符合现场玩法。

### 阶段 6：部署演练与小范围试用

将已验证发布包部署到隔离实例，模拟工作人员与两名玩家；记录完整一次“建用户→下发→答题→拿线索→领取→核销→再次下发”。补齐部署/回退文档后再切正式入口。

切换前停止旧业务写入并做最终备份。正式部署采取管理员确认的维护窗口；先建立新表，再部署匹配的后端和前端。旧集合先停用而不是顺手全部删除，验证无其他使用方后再按清单清理。

已有新业务写入后发生问题，先暂停新答题和核销并保留新库快照；不能直接恢复旧备份覆盖已领取奖品、经验和核销记录。优先前向修复；必须恢复时由管理员确认数据核对方案。

## 2. 必须通过的测试

| 类别       | 关键用例                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| 认证与权限 | 注册被拒绝；账号/昵称分离；普通玩家不能访问后台；不能借 ID 或直接调用集合 API 越权；账号禁用及时生效      |
| 资料与密码 | 初次改密；旧密码错误；重置流程；头像类型、大小、内容验证；不能注入账号状态/权限字段；会话失效语义实际验证 |
| 等级与时间 | 等级上下边界；未达标预分配；开始后升级越上限；重发重新检查；截止瞬间拒绝；改本地时钟无效                  |
| 判题与顺序 | 填空标准化；单选错误；下一题锁定；永久锁定；人工通过；完成后再提交不惩罚也不发奖                          |
| 重试与并发 | 错误答案重试只计一次；正确答案重复提交只结算一次；同键不同请求被拒绝；响应丢失后恢复；两个设备并发提交    |
| 经验与奖励 | 同关只加一次；重新下发再次正常加；事务失败全部回滚；流水可核对；人工调整有原因且总数非负                  |
| 核销       | 用户不能核销；管理员双击/并发；撤销误核销有审计；真实柜码不出现在通用日志或他人接口                       |
| 内容与版本 | 发布后不可原地修改；草稿不影响运行中场次；旧版本归档仍可回顾；线索和叙事只有解锁后可读                    |
| 通知与缓存 | 定向发送；批量发送重试不重复；跨设备已读；换账号无旧数据残留；后台页面暂停/恢复轮询                       |
| 运维       | 容器重建不丢数据；备份可恢复；外部媒体范围明确；空库可迁移；前后端契约版本不匹配给出明确错误              |

优先复用当前 Vitest/Playwright 覆盖和组件夹具，按变化补齐服务端集成测试。仅在 mock API 上通过前端测试不足以证明权限、事务或文件访问安全。

## 3. 1Panel 容器落地方式

运行二进制本身没有问题。当前需要补齐的是可重复的代码发布、持久化数据目录、备份和测试环境，而不是让用户另学一套服务器架构。

下面只是目标示意，不是已确认的现有路径：

```text
容器内 /pb/
  pocketbase           # 固定版本二进制
  pb_hooks/            # 本版本业务代码
  pb_migrations/       # 本版本数据库迁移
  pb_data/             # 必须挂载到宿主机的持久目录
```

正式发布建议把二进制、hooks 和 migrations 一起打包进固定版本镜像；数据目录单独挂载。不依赖手动修改容器临时文件系统来保存业务代码或数据库。若先沿用上传文件方式，也要保存匹配的版本化发布包并配置持久目录，禁止容器重建后丢失文件。

测试容器使用独立数据目录、端口和访问入口，绝不能与正式容器共享同一个 `pb_data`。首次可以先在本机运行测试，不必等远程测试域名准备好才开发。

迁移文件在对应版本中经过验证后执行。官方支持启动时应用尚未执行的迁移；因此上传新迁移并重启就可能改变数据库，不能把“只换个文件”误当成无风险操作。日常通过业务管理系统维护内容，不直接在生产 PocketBase Dashboard 随意改 schema。[迁移文档](https://pocketbase.io/docs/js-migrations/)

容器数据需要持久化挂载。内置备份覆盖本地数据和本地上传文件，不覆盖外部 S3 文件或旧 CDN/AList 素材；这些需单独备份或确认不清理。[部署与备份文档](https://pocketbase.io/docs/going-to-production/)

反向代理保留 HTTPS，按实际头像限制协调上传大小和超时。登录和答题接口限速；超级管理员维护入口单独保护。具体 1Panel 点击步骤在确认版本和当前容器配置后给出，不猜测界面路径。
